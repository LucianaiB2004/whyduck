## 外部联调与部署边界

用户提供密钥后，已写入本地受限于源码排除规则的服务端 `.env`，不写入前端或源码包。`npm run verify:live -- --all` 实际完成千问文本、图片提取和群聊接力，退出码 0。图像测试使用无真实个人信息的合成订单，确认金额 199 被提取且保持待人工核对；群聊实测调用顺序为管家鸭、后手鸭、管家鸭汇总。记录见 `artifacts/live-verification.json`，仅记录验证项目及 token 用量，不包含密钥。这不证明每个角色、所有真实凭证或全部售后情况都已验证。

初次实网调用暴露可选字段 null 与格式不符，已规范化为缺失值；保持来源校验并增加最多一次格式纠正，仍拒绝未知证据、伪引文和越权工具。联调中的失败如实暴露，没有伪造结果。

支付宝 APPID、应用私钥、支付宝公钥、服务器域名白名单及 AI 平台相关权限未配置。身份授权实网、IDE 编译、真机、平台安装、审核发布与比赛提交未执行。未实现或声称具有支付宝订单读取、支付账单读取或代退款权限。

环境没有可执行的 Docker 命令，镜像构建未执行；Dockerfile 已提供。正式生产构建本地运行验证不等于容器、HTTPS 反向代理或公开站点部署验证。

## 审查与已修问题

其他实现者对后端和 AI 进行独立审查，发现支付宝身份重复关联及报告引用丢失，均已修复并加入回归测试。平台适配作者对其自己编写的适配部分不算独立审查。主代理另行检查最终集成，修复上传原件重编码、过期快照覆盖、旧任务取消、重试关联、模型接力记录、Windows 文件监听异常与生产 SQLite 导入问题。

当前应用采用单实例 SQLite 与私有本地文件；多实例扩展、队列和对象存储迁移不属于已验证部署能力。报告默认处理手机号、邮箱及长编号，导出前仍需用户检查其他自由文本信息。

## 真正需要项目所有者办理

1. 在服务器受限 `.env` 配置已开通的千问密钥，然后执行 `npm run verify:live` 并用自己的获准材料核对视觉效果。
2. 使用自己的支付宝开发者身份完成应用、能力申请和服务器域名配置，按集成文档完成沙箱/真机及正式授权。
3. 需要上线时确定 HTTPS 域名和服务器并授权部署；实际比赛资格、最终材料和提交由项目所有者确认。

这些事项不会影响本地账户、案件、上传、核对、任务、草稿和报告的真实使用。
