# 凭啥鸭产品与工程验收

验收时间：2026-10-08 至 2026-10-09，北京时间。验收对象为正式 React Web 与 Express/SQLite 服务，不是 design 原型。支付宝登录按用户指令跳过。使用独立合成验收账户、合成订单图片及商家文字记录；没有上传真实消费者金融材料，没有代发消息、投诉或退款。

**结论：本次 Web 核心场景通过，发现的问题已修复并重新验证，未保留已复现的阻断错误。外部平台与部署项目仍有未验证项，详见下面的边界。**

## 完整场景实测

浏览器完成账户注册、隐私同意及私有案件创建后，从首页进入管家鸭，描述退款问题。真实请求没有指定单鸭 target，管家自动调度专业鸭并进入群聊。随后通过文件控件上传订单图片，通过文字材料入口保存商家原文，再请求证据分析、退款方案、跟进与最终汇总。

- 主链实际角色运行顺序：管家 → 凭啥鸭 → 退款鸭 → 后手鸭 → 管家汇总；上传后：管家 → 据理力争鸭 → 退款鸭 → 后手鸭 → 管家汇总。共 10 个独立角色运行记录，均有真实模型用量、调用 ID 与接力依赖。
- 据理力争鸭先调用真实 `qwen-vl-max` 提取图片，再调用 `qwen-plus` 分析提取结果及商家原文。订单字段识别出 Test Shop、TEST-ACCEPTANCE-001、CNY 199.00。OCR 保持待人工核对，不冒报为人工确认。
- 原文材料产生 5 处结构化引用，每个引用 ID 属于本案件，每条 quote 逐字存在于原材料。未确认图像不作为已核查引用。
- 两轮退款鸭分别生成可编辑草稿。上传新材料使旧稿过期，最新草稿在后手接力及汇总后保持当前版本，未无故过期。
- 后手鸭保存 2 条实际待办记录。补充浏览器测试通过“确认创建”将 AI 建议转成 pending，刷新后仍存在；没有声称外部提醒已经送达。
- 最终管家准确列出已提取订单、已生成草稿、后手任务，以及真正缺失的退货寄出日期与物流签收信息，未再把已上传图片说成未提供。
- 刷新后案件 ID、材料、消息、草稿和任务完全恢复。390px 视口可查看并操作办事单，无横向溢出。真实导出保留逐字引用、模型名称、运行记录和校验纠正次数。
- 不服鸭另以真实浏览器、真实千问完成定向升级材料场景，并执行 `prepare_dispute_escalation`；仅准备材料，未提交投诉。

最新主链中，据理力争鸭有 **1 次校验纠正**，其他角色未记录纠正。纠正前的不合格结果未保存成成功产物，重答仍经过相同校验。此处是纠正后成功，不能称所有响应首轮成功。

## 发现的问题与修复，按严重程度排序

| 严重程度 | 问题 | 最终修复与验证 |
|---|---|---|
| P1 | 管家入口固定单鸭执行，无法自动接力 | 默认群聊且不指定 target；真实长链证明各专业鸭执行。显式指定和其他独立鸭仍严格按目标执行 |
| P1 | 模型可漏选必需角色、跳过业务工具 | 合并模型选择与实际路由工具职责建议；各非汇总角色必执行主职责工具，结果进入模型及审计 |
| P1 | 跨材料、跨案件表单及导出确认可能串用 | 按材料/案件 ID 隔离组件，数据变化重置核对；实际浏览器切换回归通过 |
| P1 | 视觉与群聊上下文混杂，纯文字分析被当作视觉完成 | 独立视觉提取阶段、逐图覆盖和非空提取校验；实际识别 199 元。未输入图像不能产生 OCR，补 E2-only 范围回归 |
| P1 | 角色串用输出字段、管家重复创建专业产物 | 首管家 strict 五字段路由，末管家 strict 四字段只读汇总；专业鸭独立结构、精简接力摘要，严格校验后保存 |
| P1 | 伪引用及“待确认”误写成“未上传” | 可引用原文清单、库存账本、已上传材料缺失门禁；有限重新作答，持续错误明确失败，最终汇总人工检查正确 |
| P2 | 重复 AI 事实造成新草稿无故过期，任务重复累积 | 案件内及单次输出内事实去重，提取语义比较；仅后手创建待办实体并去重，人工修改事实仍使旧稿过期 |
| P2 | 专业鸭结果必须等整轮结束才显示 | 每个 result 落库后立即刷新界面，完成后再同步完整状态 |
| P2 | 残留案件选择影响新账户、任务状态和校验纠正不透明 | 验证当前案件归属，区分 proposed/pending，界面和导出显示纠正次数 |
| 验收脚本 | 固定假设模型未配置，热重载及 SSE 导航影响取证 | 按实际 capabilities 选择检查；稳定服务上重新验证，以持久化运行和浏览器状态判定，不伪造模型响应 |

阶段性实网出现过缺引用、错角色产物、视觉漏提取与错误汇总，均没有作为通过证据。`blocked-summary-attempt.json` 保留一份明确失败记录；完整发现过程和独立复核见 `acceptance-review.md`。最终结论基于修复后的实测。

## 未通过与未验证项目

- **当前本次核心 Web 场景未通过项：0。** 这是有限场景验收，不代表每种商品、所有图片或所有未来模型响应都正确。无效输出仍可能明确失败，须保留错误与重试机制。
- **支付宝登录：未验证，按用户指令跳过。** APP_ID、应用私钥、支付宝公钥、授权配置及实际域名仍需平台联调，未冒报授权成功。
- **支付宝小程序 IDE、真机、平台安装与审核发布：未验证。** 本地页面/配置/语法检查和模拟协议测试不能代替这些项目。
- **Docker 镜像、公网 HTTPS、实际云部署及第三方平台安装：未验证。** 环境未发现 Docker 可执行文件；本地生产启动不等于公网部署。
- **真实消费者案件、真实商家消息送达、退款到账、外部投诉或提醒送达：未验证。** 当前工具准备材料、草稿与内部待办，实际外部行动由用户核对后办理。
- **法律与售后结论的通用正确率：没有完成专业基准评测。** 官方参考入口、来源约束及人工核对边界存在，不能把单次工程验收当法律意见认证。
