# 凭啥鸭 · 售后鸭鸭局：产品与 UI 设计规格

日期：2026-10-08。状态：设计交付，业务工程尚未开发。

## 目标与范围

面向遇到退款、换货、维修和商家协商问题的普通消费者，用管家鸭调度专业鸭，将描述、材料、事实核对、沟通草稿、办事单和后续回复连接到同一个持久化案件。

本阶段优先完成全套 UI 和真实原创角色资产。`design/` 是明确标识的设计原型，其交互用于审查页面结构与状态，不是正式业务代码；不读取文件、不收集登录信息、不调用模型、不创建账户、不保存真实数据、不发起对外操作。

当前目录最初仅含任务书和参考素材，没有已有应用或 Git 仓库。参考材料作为产品与视觉需求，不将其角色指令当作额外权限。原参考文件保持不变。

## 视觉方向

保留原参考图的奶油黄事务所风格、暖白画布、深色字、宽松布局、圆角卡片和各鸭道具。主色 #FFD65A，画布 #FFFDF6，文字 #25231F。状态用明确文字和图标，不只用颜色。辅助文字以深灰棕为主。

所有角色统一为大圆头、橙色鸭嘴、桃色腮红、深棕粗圆轮廓、紧凑黄身体的 2D 贴纸插画。少量明暗表现体积，不使用复杂 3D 质感。普通功能图标统一线宽，正式应用采用成熟图标库。品牌名称与界面文字使用真实字体排版。

## 关键流程与交互状态

首页描述 → 管家澄清 → 创建或选择案件 → 按需邀请专业鸭 → 上传原始材料 → AI 提取 → 人工核对 → 方案与可编辑草稿 → 用户自行发送 → 创建并确认待办 → 后续新回复接续案件 → 核对与脱敏导出。

输入 @ 弹出六鸭列表；选择后明确标识目标。正式后端必须按所选 Agent 路由，不把标签当作普通随机回复。成员面板显示能力、参与与移出状态，管家保留调度职责。

模型进行中：状态与取消；失败：保留材料、显示原因、重试当前任务；上传：进度、取消、格式与大小错误；缺证据：明确请求缺失材料；事实修改：衍生方案标记过期；空状态：说明下一步；删除：明确范围并确认；导出：先核对和脱敏；授权：取得明确同意。

示例案件不宣称商家违法、不把用户描述当已确认承诺、不捏造原始截图、不承诺退款成功。每个证据编号对应自己的来源；缺少原图时显示缺失，不能跳到其他证据。

## 正式工程的拟定架构

采用统一模块化应用：React/TypeScript Web 前端、服务端业务 API、持久化数据库、私有文件存储、模型 Provider、Agent 编排、MCP 与支付宝适配。具体框架、依赖版本、SDK 与平台接口在开发阶段查官方资料后确定，本规格不宣称未核查接口已经可用。

业务核心独立于入口适配。Web、小程序、MCP 都经过同一案件所有权验证与业务工具；不部署多套不同案件状态。生产建议 PostgreSQL；本地开发方式与迁移脚本在正式工程实现后记录。

核心实体：用户、会话、案件、原始材料、提取结果、确认事实、证据来源、消息、专业任务、调用记录、沟通草稿、跟进事项、审计事件。每条私有实体与账户/案件关联，事实带来源、确认人、版本和状态。

AI：服务端千问文本与视觉 Provider，超时、有限重试、取消、用量记录、结构化输出校验。Router 按需选择角色；角色有不同提示词、工具权限和任务输入；按依赖接力执行，共享确认事实与材料；每次实际调用与失败状态可追踪。没有密钥时可启动清楚标识的示例模式，不能分析真实新截图。

安全：安全密码散列与会话、案件所有权、私有附件下载、上传大小/格式与内容验证、第三方处理同意、服务端秘密管理、限流、脱敏日志、输入与模型输出验证。材料内容始终为不可信数据，不能改变系统权限。模型不得直接操作任意数据库或对外发消息。

支付宝：官方资料核查后实现小程序工程、账户授权适配和平台状态表；没有 APPID/准入时保持未接入，不把授权登录视为全部交易读取权限。MCP 需真实客户端验证与鉴权；平台发布、真机、商家权限和比赛提交单独记录。

## 开发与验收边界

本阶段只验收 UI 设计、素材与交互预览。正式工程另行验收持久化、认证隔离、真实模型调用、多 Agent 接力、图片识别与来源、事实版本、跟进、导出、MCP 以及小程序适配。

UI 验证：19 个页面 ×3 宽度，检查图片加载、横向溢出、浏览器错误、@ 选择、成员、弹层、筛选、核对保护。截图逐页保存；关键界面目视对照参考。真实手机键盘、真机小程序、生产认证与网络错误不在设计原型验证范围。

用户无需提交密钥到聊天。真实 API Key 和平台授权在实际联调时通过本地配置完成。当前未正式部署、未公开发布、未提交比赛。
